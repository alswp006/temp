# iOS 단축어 — 사진 한 장으로 기록

Phase 1의 목표는 **앱 개발 0**으로 매일 쓰는 것입니다. iOS 단축어와 텔레그램 봇이
그 클라이언트입니다. 이 문서는 단축어 쪽입니다.

## 왜 단축어인가

* 공유 시트에 들어갑니다. 사진 앱에서 식판 사진을 고르고 → 공유 → **식판 기록**.
* 잠금화면·제어센터·액션 버튼(iPhone 15 Pro 이상)에 붙습니다. 카메라를 열고
  찍고 공유하는 과정이 버튼 하나가 됩니다.
* 촬영 시각이 그대로 넘어가므로 끼니 판정이 정확합니다.

목표는 **끼니당 15초 이하**입니다.

---

## 1. 토큰 발급

PWA → **더보기** → (개발자 콘솔이나 `curl`로도 됩니다):

```bash
curl -X POST https://<your-host>/api/auth/tokens \
  -H "Authorization: Bearer <액세스 토큰>" \
  -H "Content-Type: application/json" \
  -d '{"name":"iPhone 단축어"}'
```

응답의 `token` (`sk_…`)은 **이때 한 번만** 보입니다. 잃어버리면 재발급하십시오.

---

## 2. 단축어 만들기 — 식사 기록

단축어 앱 → 새 단축어 → 아래 순서대로.

| # | 동작 | 설정 |
|---|---|---|
| 1 | **입력 받기** | 유형: 이미지 / 입력이 없으면: **카메라로 찍기** |
| 2 | **텍스트** | `sk_…` (발급받은 토큰) — 이름을 `TOKEN`으로 |
| 3 | **텍스트** | `https://<your-host>` — 이름을 `HOST`로 |
| 4 | **URL 콘텐츠 가져오기** | 아래 참조 |
| 5 | **사전에서 값 가져오기** | 키: `id` |
| 6 | **알림 표시** | `접수했습니다 (#{id})` |

**4번 상세**

```
URL      : {HOST}/api/meals/photo
방법      : POST
헤더      : Authorization = Bearer {TOKEN}
요청 본문  : 양식 (Form)
  file        = (1번의 이미지)          ← 유형을 "파일"로 지정
  canteen_id  = 3                       ← 선택. 식당 ID
  shot_at     = (현재 날짜, ISO 8601)    ← 선택. 사진의 촬영 날짜를 쓰면 더 정확
```

`shot_at`을 넣지 않아도 서버가 사진 EXIF의 촬영 시각을 읽습니다. 갤러리에서 고른
과거 사진도 올바른 날짜·끼니로 들어갑니다.

> **사진 크기.** 단축어의 **이미지 크기 조절** 동작을 4번 앞에 넣고 긴 변을
> 1600px로 맞추면 업로드가 눈에 띄게 빨라집니다. 서버도 어차피 1568px로 줄이므로
> 손해가 없습니다.

---

## 3. 액션 버튼 / 잠금화면에 붙이기

* **액션 버튼**: 설정 → 액션 버튼 → 단축어 → *식판 기록*
* **잠금화면**: 잠금화면 편집 → 위젯 추가 → 단축어
* **공유 시트**: 단축어 상세 → 세부사항 → *공유 시트에 보기* 켜기, 입력 유형 이미지

---

## 4. 두 번째 단축어 — 체중

체중은 대리 입력이 불가능하고 매일 한 번뿐이라 별도 단축어가 편합니다.

| # | 동작 | 설정 |
|---|---|---|
| 1 | **입력 요청** | 숫자, 프롬프트: `오늘 체중` |
| 2 | **URL 콘텐츠 가져오기** | `{HOST}/api/weights`, POST, JSON 본문 `{"raw_kg": (1번)}` |
| 3 | **알림 표시** | `기록했습니다` |

헤더는 식사 단축어와 동일합니다.

---

## 5. 세 번째 단축어 — 운동 (받아쓰기)

| # | 동작 | 설정 |
|---|---|---|
| 1 | **텍스트 받아쓰기** | |
| 2 | **URL 콘텐츠 가져오기** | `{HOST}/api/workouts/text`, POST, JSON `{"text": (1번)}` |
| 3 | **사전에서 값 가져오기** | 키: `sets` |
| 4 | **알림 표시** | `(3번의 개수)세트 기록` |

"스쿼트 60에 10개 3세트, 랫풀 50에 12개 3세트"처럼 말하면 6세트가 들어갑니다.

---

## 6. 네 번째 단축어 — 수정

분석 결과가 틀렸을 때.

| # | 동작 | 설정 |
|---|---|---|
| 1 | **입력 요청** | 텍스트, 프롬프트: `무엇을 고칠까요` |
| 2 | **URL 콘텐츠 가져오기** | `{HOST}/api/meals/{마지막 식사 ID}/edit`, POST, `{"text": (1번)}` |
| 3 | **알림 표시** | 응답의 `message` |

마지막 식사 ID를 자동으로 찾으려면 `GET {HOST}/api/meals`를 먼저 부르고 첫 항목의
`id`를 쓰면 됩니다. (텔레그램 브리지는 이걸 자동으로 합니다 — 그냥 "밥 150으로"라고
보내면 마지막 식사에 적용됩니다.)

---

## 문제 해결

| 증상 | 원인 |
|---|---|
| 401 | 토큰이 `Bearer ` 접두사 없이 갔거나 폐기됨 |
| 422 `validation_error` | `file` 파트의 유형이 "파일"이 아니라 "텍스트"로 지정됨 |
| 끼니가 엉뚱함 | `shot_at`을 안 보냈고 사진에 EXIF가 없음. 앱에서 끼니를 고치면 재분석됩니다 |
| 계속 `pending` | 워커가 안 돌고 있음. `GET /api/healthz`의 `jobs.queued` 확인 |
| `open_mode: true` | 그 끼니의 식단표가 없음. 정확도가 떨어지며 UI에 표시됩니다 |

## 텔레그램 쪽이 더 편한 경우

단축어를 만들기 귀찮거나 안드로이드라면 텔레그램 브리지가 같은 일을 합니다.

1. 봇에게 `/link sk_…` 를 보냅니다.
2. 이후로는 **사진만 보내면** 식사가 기록됩니다.
3. `72.4` → 체중, `밥 150으로` → 마지막 식사 수정,
   `스쿼트 60에 10개 3세트` → 운동, `/오늘` → 요약.

설정은 [OPERATIONS.md](OPERATIONS.md#텔레그램-브리지)를 보십시오.
