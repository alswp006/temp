# 식판 (Sikpan)

> **기록을 나 혼자 하지 않아도 되는 앱** — 같이 쓰는 식단·운동 기록 앱.

식단 기록이 실패하는 이유는 정확도가 아니라 귀찮음입니다. 귀찮음을 없애는 방법은
둘뿐입니다. **입력을 줄이거나, 남이 대신 해주거나.** 이 앱은 둘 다 합니다.

```
사진 한 장  ─┐
음성 한 문장 ─┼→  기록  ←─  코치·친구가 대신 써준 것
1탭 재사용  ─┘
```

---

## 무엇이 다른가

| | |
|---|---|
| **객관식 인식** | 식단표가 있으면 AI는 "무슨 음식인가"가 아니라 "표준량 대비 얼마나 담았나"만 판정합니다. 열린 문제가 객관식이 됩니다. |
| **대리 기록** | 트레이너·코치·친구가 내 운동과 식단을 대신 기록합니다. 카톡으로 이미 하고 있는 일을 앱 안으로 가져옵니다. |
| **반복 학습** | 자주 먹는 식사는 두 번째부터 1탭. 확정한 끼니는 다시 인식하지 않습니다. |
| **알아서 바뀌는 목표** | 체중 추세로 실제 소비량을 역산해 매주 목표를 갱신합니다. |
| **비용이 내려가는 구조** | 같은 식당 사람이 많아질수록 1인당 AI 호출 비용이 떨어집니다. |

**급식은 간판이 아니라 엔진입니다.** 식단표 기반 객관식 인식은 정확도의 원천이지만,
겉으로 "급식 앱"이라고 내걸지 않습니다. 유저에게는 **'내 식사 세트'** 로 보이고,
급식은 그걸 사진 한 장으로 채우는 특수 케이스일 뿐입니다. 구내식당, 학식, 집밥 루틴,
단골집, 밀프렙에 같은 원리가 적용됩니다.

## 30초 만에 실행

API 키 없이도 전부 동작합니다 (`stub` 비전 프로바이더).

```bash
pip install -e ".[dev]"
make dev
# → http://localhost:8000/app/   (PWA)
# → http://localhost:8000/docs   (OpenAPI)
```

로그인은 비밀번호가 없습니다. 이메일을 넣고 **인증 코드 받기** 를 누르면 개발
모드에서는 코드가 화면에 바로 표시됩니다.

실제 모델을 붙이려면:

```bash
export VISION_PROVIDER=anthropic
export ANTHROPIC_API_KEY=sk-ant-...
# 또는
export VISION_PROVIDER=gemini
export GEMINI_API_KEY=...
```

## 한 바퀴 돌아보기

1. **더보기 → 내 식당** 만들기
2. **이번 주 식단표 보기 → 📷 주간 식단표 찍어서 올리기** — 사진 1장이 날짜·끼니별
   메뉴 목록으로 파싱되고, 확인 후 저장합니다. 한 주에 한 명만 올리면 같은 식당
   사람 전부가 씁니다.
3. **오늘 → 📷** 식판 촬영 — 즉시 접수(202)되고 분석은 백그라운드에서 돕니다.
4. 결과가 틀렸으면 **"밥 150으로"** / **"국 안 먹음"** 한 줄로 고칩니다.
5. 자주 먹는 끼니는 **내 식사 세트로 저장** → 다음부터 1탭.
6. **더보기 → 초대 만들기** 로 코치·친구를 연결합니다. 멘티는 연결 **전에** 권한
   화면을 보고 항목별로 켭니다.

## 아키텍처 한눈에

```
                        ┌──────────────────────────────┐
   PWA (무빌드)  ──────▶│  FastAPI                     │
   iOS 단축어    ──────▶│   ├─ /api/*                  │
   텔레그램 봇   ──────▶│   ├─ 권한·감사 로그           │
                        │   └─ 인식 파이프라인          │
                        └───────┬──────────────────────┘
                                │ enqueue
                        ┌───────▼──────────┐   ┌──────────────────┐
                        │ 내구성 잡 큐      │──▶│ VisionProvider    │
                        │ (jobs 테이블)     │   │  anthropic/gemini │
                        └───────┬──────────┘   │  /stub            │
                                │              └──────────────────┘
                        ┌───────▼──────────────────────────────────┐
                        │ SQLite (1인) / PostgreSQL (그 이상)        │
                        └──────────────────────────────────────────┘
```

인식 파이프라인:

```
사진
 └ 촬영 시각(EXIF) → 끼니 판정
 └ 식당 + 날짜 + 끼니 → 식단표 조회
      ├ 있음 → 메뉴 후보 N개 주입 (객관식 모드)
      └ 없음 → 열린 인식 모드 (결과에 "오차 큼" 표시)
 └ 비전 모델 K회 병렬 호출        ← K는 상수가 아니다 (아래)
 └ 항목별 portion_ratio 중앙값 + 등장 빈도로 신뢰도 계산
 └ 메뉴 → 식약처 food_code 매칭 → 100g당 영양소 × 실제 중량
 └ 개인 보정계수 적용 → 저장 → 알림
```

**K가 상수가 아닌 이유.** 그 (식당, 날짜, 끼니) 슬롯을 **처음** 찍는 사람은 K=5를
내고 "기준 해석"을 남깁니다. 이후 사람은 K=1만 내고, 기준과 어긋날 때만 3회를
추가합니다. 같은 식당 유저가 많아질수록 1인당 단가가 내려가고, 확산 인센티브와
비용 구조가 같은 방향을 봅니다.

자세한 설명은 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 대리 기록의 안전장치

대리 기록은 위험한 권한입니다. 네 가지가 코드로 강제됩니다.

| 규칙 | 어디서 강제되나 |
|---|---|
| **표시** — 모든 레코드에 작성자 배지 | `Meal.logged_by`, `Workout.logged_by` → API가 `logged_by_name` 반환 |
| **되돌리기** — 멘티는 언제든 수정·삭제 | 소유자 경로는 스코프 검사 없이 통과 |
| **로그** — 모든 대리 행위 기록 | `app/services/audit.py`, 멘티가 `/api/audit-log`로 열람 |
| **체중은 대리 입력 불가** | `Scope`에 `weight:write`가 **아예 없습니다**. `POST /weights`는 `user_id` 파라미터 자체를 받지 않습니다 |

목표 설정도 코치 마음대로 할 수 없습니다.

* 목표 칼로리가 추정 기초대사량 아래면 **저장 자체가 거부**됩니다 (`422 safety_guard`).
* 주간 감량이 체중의 1%를 넘으면 **멘티 본인 확인**을 한 번 더 받습니다.
* 코치의 제안은 멘티가 수락하기 전까지 효력이 없습니다 (`accepted_at is null`).

`tests/test_permissions.py`가 이 규칙들을 하나씩 검증합니다.

## 배틀에서 체중을 뺀 이유

점수 규칙에 체중 **수치**가 들어가지 않습니다. 기록했다는 사실만 1점입니다.

1. 감량 속도 경쟁은 무리한 절식을 유도합니다. 지인끼리 하면 압박이 더 큽니다.
2. 시작 체중이 무거운 사람이 자동으로 유리해서 게임이 안 됩니다.
3. 체중은 통제 불가능하지만 기록은 통제 가능합니다. 통제 가능한 것으로 겨뤄야
   계속합니다.

체중 절대값은 설정으로도 공개할 수 없습니다. 패배 벌칙·랭킹 강등·연속 실패 알림도
없습니다. 미기록일에는 점수가 0일 뿐 아무 메시지도 보내지 않습니다.

## 정직하게 말해두는 한계

* **번들된 영양 DB는 시작용입니다.** `app/data/foods.csv`는 급식·한식 중심 약 150건의
  근사값입니다. 프로덕션은 식약처 식품영양성분 통합 DB(약 9.2만 건)를
  `scripts/import_mfds.py`로 교체하십시오. 매칭·계산 코드는 그대로 동작합니다.
* **`stub` 프로바이더는 진짜 인식을 하지 않습니다.** 사진 바이트의 해시로 결정론적인
  답을 만듭니다. 파이프라인·집계·캐시·UI를 키 없이 전부 돌려보기 위한 것이고,
  테스트와 CI가 이걸로 돕니다. 정확도 판단의 근거가 될 수 없습니다.
* **오차는 남습니다.** 식판은 AI가 제일 어려워하는 사진입니다. 객관식 모드와 K회
  중앙값이 오차를 줄이지만 없애지는 못합니다. 기름 흡수량은 특히 과소추정되며,
  2주 저울 캘리브레이션이 이걸 개인별로 보정합니다.
* **운동 소모 칼로리는 적응형 TDEE에 넣지 않습니다.** 체중 추세에서 역산한 소비량에
  이미 운동이 포함돼 있어 이중 계산이 됩니다. 표시용·추이용입니다.


## 만들지 않을 것

커뮤니티 피드, 캐릭터 육성, 포인트·재화 경제, 카운트다운 타이머, 스트릭 끊김 경고,
붉은 숫자, "초과했습니다" 알림, 하루 2회 이상 푸시, 영양제 커머스.

전부 리텐션에 도움이 되지만, 전부 "기록이 쉬워지는 것"과는 무관합니다. 하나라도
넣고 싶어지면 그 시간에 입력 시간을 1초 줄이는 게 낫습니다.
